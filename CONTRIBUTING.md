# Working agreement

## Branching

- `main` is the integration branch. It must always build.
- Work happens on short-lived branches cut from `main`:
  - `feat/<short-name>` — new functionality
  - `fix/<short-name>` — bug fix
  - `chore/<short-name>` — tooling, docs, config
- Rebase on `main` before opening a pull request. Delete the branch after merge.

## Commits

Conventional Commits:

```
<type>(<scope>): <subject>
```

Types: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `perf`.

Examples:

```
feat(auth): add email login
fix(api): handle empty payload on /submit
```

Subject in the imperative, under 72 characters, no trailing period.

## Pull requests

- One PR per logical change; keep it small enough to review in 15 minutes.
- Fill in what changed, why, and how it was tested.
- One approval required before merge. Squash on merge.
- Never push directly to `main` once the team is more than one person.

## How we meet

Four fixed slots. Everything else is asynchronous.

| When | What | Length | Who |
| --- | --- | --- | --- |
| Monday | Sprint planning | 60 min | Everyone |
| Daily | Written stand-up in the team channel | — | Everyone |
| Friday | Demo & integration | 45 min | Everyone |
| As needed | Deep dive on one problem | 45 min | Only those involved |

### Monday planning (60 min)

1. **Roadmap check (10 min)** — are we on the sprint exit criterion? If not, what changes:
   scope, owner, or date. Pick one.
2. **Per-role round (25 min, 5 min each)** — what shipped, what is next, what is blocked.
3. **Blockers (15 min)** — each blocker leaves the room with an owner and a date.
4. **Commitments (10 min)** — each owner states what will be demoable on Friday.

### Daily written stand-up

Three lines in the team channel, no meeting, before you start work:

```
shipped:  what landed since last time (link the PR)
next:     what you are doing today
blocked:  what you need from whom, or "nothing"
```

A `blocked:` line that repeats for two days goes to the Monday blockers slot, or sooner if
it touches data and replay.

### Friday demo & integration (45 min)

Working code only — no slides, no "almost done". Each owner runs their thing on a clean
clone of `main` while everyone watches. What cannot be demoed is not done. Last 15 minutes:
merge conflicts, integration problems, and what moves into next week.

### Sprint review & retro (last Friday of a sprint, +30 min)

Against the sprint exit criterion: did we hit it, and what changes next sprint. Retro is
three questions — keep, stop, start — and produces at most two changes to how we work.

### Rules

- **No agenda, no meeting.** Post it beforehand; cancel if there isn't one.
- **A decision made in a meeting that is not written down did not happen.** Log it in
  [`docs/decisions.md`](docs/decisions.md) the same day.
- **Escalate within 24 hours.** A blocker held quietly for a week costs the team a sprint.
- **If it can be a message, make it a message.** Stand-ups are written for this reason.
- **Deadlines are fixed; scope is not.** When something slips, cut scope and say so — never
  quietly move the date.

## Definition of done

- [ ] Code runs on a clean clone with the documented command
- [ ] `python -m pytest` and the dashboard checks pass
- [ ] Reported numbers are regenerated by a command in the repository, not pasted by hand
- [ ] Docs updated if behaviour changed
- [ ] No names, unit names, logos or identifying metadata added
- [ ] Reviewed and approved
